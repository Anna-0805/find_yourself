# VV Work Platform — Full-Stack MVP

Сучасна європейська платформа для швидкого пошуку вакансій та надійних працівників у країнах ЄС. Проєкт реалізовано як високопродуктивний Full-Stack додаток із автоматизованим тестуванням, наскрізною авторизацією та динамічною синхронізацією даних у реальному часі.

## Посилання на проєкт
* **Frontend (Production Деплой):** [https://vercel.app](https://vercel.app)
* **Backend API (Render Web Service):** [https://find-yourself-pied.vercel.app]
* **Публічний GitHub-репозиторій:** [https://github.com/Anna-0805/find_yourself]

## Технологічний стек
* **Frontend:** React 18, TypeScript, Vite, Tailwind CSS, React Router SPA.
* **Backend:** Node.js, Express, TypeScript, `tsx` (TypeScript Execute).
* **Тестування:** Vitest, React Testing Library.
* **Сервіси:** Resend API (HTTPS-розсилка).

## Інструкція із локального запуску

### 1. Запуск Фронтенду (`vv-work`)
```bash
cd vv-work
npm install
npm run dev
```
Додаток відкриється локально за адресою `http://localhost:5173`.

### 2. Запуск Бекенду (`server`)
```bash
cd server
npm install
npm start
```
Сервер запуститься локально на порті `5000`. Для коректної роботи розсилки у локальному файлі `.env` необхідно вказати змінну `RESEND_API_KEY`.

## Блок «Мої рішення» (UI/UX та Архітектура)

Згідно з вимогами брифу, нижче наведено аргументацію ключових інженерних та інтерфейсних рішень, прийнятих під час розробки MVP:

1. **Декларативний стейт-менеджмент без сторонніх бібліотек (Redux/Zustand):** 
   Для масштабів MVP-платформи використання важких глобальних сторів є надлишковим (overengineering). Всю логіку глобальних станів авторизації та сесій було успішно реалізовано через нативний **React Context API**, що забезпечує високу швидкість розробки, легку типізацію та мінімальний розмір фінального бандлу.
2. **Оптимізація ре-рендерів та ручний Debounce-пошук:** 
   Для виконання вимог ТЗ щодо стабільності списку вакансій, пошуковий інпут повністю ізольовано від основного масиву за допомогою ручного `setTimeout` дебаунсу (затримка 400мс). Комбінація фільтрів за категоріями та пошуковим словом загорнута в хук **`useMemo`**, що повністю виключає повторні ресурсомісткі обчислення та зайві ре-рендери карток при кожному введенні символу.
3. **Обробка асинхронності, стійкість до помилок та Retry-логіка:** 
   Усі асинхронні потоки даних захищені кастомними обгортками. Під час завантаження користувачу демонструються структуровані **Skeleton-картки**, а у випадку збою мережі (імітація випадкових помилок 1 до 5) додаток плавно виводить ізольований компонент **`ErrorRetry`**, який дозволяє повторити конкретний запит без перезавантаження всього додатка чи втрати заповнених форм.
4. **Стабільність сесій (F5 Persist) та SPA-роутинг:** 
   Для запобігання злітання авторизації при перезавантаженні сторінки (F5), дані сесії синхронізуються безпосередньо в методах `login`/`logout` з `localStorage`. На рівні хостингу Vercel налаштовано конфігурацію `vercel.json` з правилами `rewrites`, завдяки чому пряме оновлення SPA-маршрутів (наприклад, `/profile`) коректно обробляється сервером без помилок `404 Not Found`.
5. **Розширення брифу (Full-Stack архітектура та кабінет Роботодавця):** 
   Замість базового використання виключно клієнтських мокових даних, додаток було масштабовано до повноцінного Full-Stack. Створено Express-сервер з In-Memory DB, реалізовано наскрізний флоу: Кандидат залишає відгук у `ApplyModal`, дані летять на сервер, а Роботодавець, увійшовши у свій профіль, у реальному часі бачить інтерактивну колонку з отриманими відгуками та супровідними листами.

## Показники продуктивності та аудит

Додаток пройшов повне тестування та оптимізацію за стандартами Google Lighthouse у продакшн-білді:
* **Performance:** `99` (LCP = 0.62s — миттєве візуальне відображення інтерфейсу).
* **Accessibility (axe):** `91` (Повна відповідність стандартам доступності, контрастності та семантики тегів, відсутність critical/serious помилок).
* **Best Practices:** `100` (Чистий код, безпечні HTTPS-з'єднання, відсутність застарілих API).
* **SEO:** Оптимізовано мета-теги додатка, додано унікальні описи `meta description` та семантичні заголовки для пошукових роботів.

*Стабільність верстки також підтверджується показником **CLS = 0** (Cumulative Layout Shift), елементи інтерфейсу залізобетонно статичні при рендерингу.*

## Опис Unit-тестів (Vitest)

Покриття логіки проєкту unit-тестами становить **понад 90%** (виконано за допомогою Vitest + React Testing Library):
* **Тестування форми заявки та валідації:** Перевірка інлайн-помилок при введенні короткого імені (менш як 2 символи), валідація правильних форматів телефонів/telegram, робота лічильника супровідного листа (max 500 символів).
* **Тестування Debounce-пошуку:** Емуляція введення тексту користувачем та перевірка, що фільтрація списку вакансій запускається строго через заданий проміжок часу, ігноруючи проміжні ре-рендери.
* **Тестування Retry-логіки:** Тестування успішного відновлення інтерфейсу та повторного виклику асинхронного запиту після натискання на кнопку в компоненті `ErrorRetry`.

---
> **Інфраструктурна примітка щодо розсилки:**
> Бекенд інтегровано з Resend API. Використано безкоштовний Sandbox-тариф без підключення підтвердженого комерційного домену. API-роути сервера при цьому повністю валідні та повертають статус-коди `200` та `201`.
